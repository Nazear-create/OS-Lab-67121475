2. I/O Bound Concept:
งานประเภท I/O Bound มีข้อจำกัดหลักอยู่ที่ความเร็วในการอ่านหรือเขียนข้อมูล เช่น เมื่อดิสก์ส่งข้อมูลได้ช้ากว่าที่โปรแกรมต้องการ 
โปรเซสจะเข้าสู่สถานะรอ I/O และยังไม่สามารถใช้ CPU ประมวลผลขั้นตอนถัดไปได้ ระหว่างนั้น ระบบปฏิบัติการสามารถมอบ CPU 
ให้โปรเซสอื่นที่พร้อมทำงานได้ แต่ถ้าไม่มีงานพร้อมประมวลผล CPU ก็อาจว่างและมีอัตราการใช้งานต่ำ ดังนั้น 
การที่โปรเซสหนึ่งเป็น I/O Bound จึงไม่ได้แปลว่า CPU ของทั้งระบบจะต้องหยุดทำงานตามไปด้วย

3. AI Industry Connection (Phase 3):
Dataset ที่ประกอบด้วยภาพแยกกันถึง 1,000,000 ไฟล์ สร้างภาระให้ระบบจัดเก็บข้อมูล เพราะต้องเข้าถึงข้อมูลกำกับ ตรวจสอบสิทธิ์ 
และเปิด–ปิดไฟล์จำนวนมาก หากขั้นตอนเหล่านี้ส่งข้อมูลเข้า GPU ได้ไม่ทัน GPU จะต้องรอแทนที่จะคำนวณต่อ ภาวะนี้เรียกว่า 
GPU starvation ซึ่งทำให้ระยะเวลาฝึกโมเดลเพิ่มขึ้น แนวทางหนึ่งคือจัดข้อมูลรวมเป็นไฟล์หรือแบ่งเป็นชุดไฟล์ที่รองรับการอ่านต่อเนื่อง
เช่น TFRecord หรือ WebDataset เพื่อลดจำนวนครั้งในการจัดการไฟล์และสนับสนุนการอ่านข้อมูลล่วงหน้า วิธีนี้ช่วยให้กระบวนการโหลด
ข้อมูลป้อนงานแก่ GPU ได้สม่ำเสมอขึ้น โดยผลที่ได้ยังขึ้นอยู่กับวิธีจัดเก็บและรูปแบบการเรียกใช้ข้อมูล

ในการทดลอง การอ่านไฟล์ขนาดเล็ก 1,000 ไฟล์ใช้เวลา 0.0507 วินาที ขณะที่การอ่านไฟล์ใหญ่เพียงไฟล์เดียวใช้เวลา 0.0010 วินาที 
เมื่อคำนวณด้วยค่าจริงก่อนปัดเศษ โปรแกรมรายงานว่าการอ่านไฟล์เล็กใช้เวลาประมาณ 52.78 เท่าของการอ่านไฟล์ใหญ่ ตัวเลขนี้สะท้อนว่า
การลดภาระจัดการไฟล์ช่วยให้การอ่านข้อมูลเร็วขึ้นในสภาพแวดล้อมที่ทดสอบ แต่ผลลัพธ์อาจได้รับอิทธิพลจากแคชของระบบด้วย
อีกทั้งการทดลองไม่ได้ตรวจวัด GPU starvation และไฟล์ที่ใช้นามสกุล .tfrecord เป็นเพียงข้อมูลไบนารีสำหรับจำลองการอ่านไฟล์ 
ไม่ได้จัดเก็บตามโครงสร้าง TFRecord จริง
